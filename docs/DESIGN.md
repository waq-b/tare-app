# Tare — DESIGN.md

The design system and build checklist for Tare. Written in D0 from `design/canvas/` (the Claude Design export, read-only).

- **Source of truth for values:** `packages/tokens/src/tokens.json` (colour, type, space, radius, touch, elevation, motion, safety levels). This file summarises it; if they disagree, the JSON wins
- **Source of truth for words and rules:** `vpt/data/*.json` (v0.1.2). The canvas uses placeholder copy (see [§5](#5-placeholder-copy-to-ignore)). Never copy canvas copy that has a data source
- **Icons:** `@tare/icons` (`Icon`, `PatternIcon`, `MuscleMap`)
- **Checked in CI:** `npm test` runs `scripts/check-design-md.ts`, which fails if a board in `design/canvas/` or a component named on the Components/Charts boards is missing here

## 1. Principles

1. **A quiet instrument.** Ink ground, warm-white text, one accent ("lume", the pale green of watch-dial paint). The app's face is calm; the pixel world belongs only to the miniquest tag
2. **Colour only when it's semantic.** `progress`, `hold`, `deload`, `swap`, `warning`, `safety-stop` each mean one thing, always with a label. Chart series colours are categories and never mean good or bad
3. **Every number in mono.** Azeret Mono, tabular, for weights, reps, times, dates-as-numbers. Instrument Sans for words
4. **One tap to log, one hand, sweaty.** Primary actions live in the bottom 40% of the screen. Touch targets ≥48px (`touch.min`), primary inputs 56–64px, focus Done 84px
5. **Nothing changes silently.** AI proposals are diffs (`DiffChip`, `ChangeCard`) the user accepts or keeps. Every change shows its rule ID, evidence strength and source
6. **Honest tools.** "Not enough data yet" beats a guess. Estimates say "estimated" (e1RM), imports say "imported" (food). Engine defaults are labelled as our synthesis
7. **Safety is fixed.** Safety screens show `safety_rules.json` wording exactly, with a lock note saying no AI can change or soften it
8. **Charts:** one y-axis, ever (stack two charts rather than dual-axis). One series = lume, no legend. Every chart has a table view one tap away. Bars start at zero
9. **Motion confirms, never decorates.** Press scale 0.97; set-done stamp; sheets rise. Reduced motion swaps movement for 120 ms fades
10. **Dark by default, light fully supported.** Every component and screen story is reviewed in both

**Tints.** The canvas uses ~40 alpha values (0.06–0.65). They're normalised into two steps per colour, emitted as `color-mix()` so they can't drift: `--<c>-tint` (12%, fills) and `--<c>-edge` (40%, borders), for `accent`, `progress`, `hold`, `deload`, `swap`, `warning`, `safety-stop`. Muscle map: `--muscle-primary` (accent), `--muscle-secondary` (accent 40%).

**Text on a tint** (`DiffChip`, `Tag`, `Banner`, selected chips) uses `--<c>-on-tint`, never `--<c>`. It has the same hue and saturation as the base colour, with lightness lowered only where needed to pass 4.5:1 on the tint over both `bg` (rows) and `surface-1` (cards). In dark every on-tint equals its base; in light, progress, swap, warning and safety-stop are darker. The fills are unchanged. Decided 2026-09-22 (#24).

### Space, radius, touch, elevation, motion

- **Space:** `--space-1..8` = 4, 8, 12, 16, 20, 24, 32, 48
- **Radius:** `sm` 8, `md` 12, `lg` 16, `xl` 20, `sheet` 28, `pill`. Canvas also uses 14 (icon buttons) and 18 (cards): map to `md` / `lg`
- **Touch:** `min` 48, `primary` 56, `primary-lg` 64, `focus` 84; `button` 60, `button-compact` 52
- **Elevation:** `elev.0` rows on ground (bg + line); `elev.1` cards (surface-1 + line, no shadow); `elev.2` sheets/dialogs only (surface-1 + line-strong + `0 12px 32px var(--shadow)`)
- **Motion:** `press` 90 ms ease-out (scale `--motion-press-scale` 0.97), `state` 160 ms, `set-done` 220 ms overshoot, `sheet` 280 ms, `scrim` 160 ms. Timer end: two haptic taps + ring flashes accent once, no sound (app behaviour, not tokens). `prefers-reduced-motion`: all durations 120 ms, linear, press scale 1

### Known contrast exceptions

From `packages/tokens/test/contrast.test.ts`, which also checks each semantic colour as text on its own tint (chips, tags, banners) over `bg` and `surface-1`. Canvas values aren't silently re-tinted; each exception has a decision.

| Pair                          | Ratio | Needs     | Decision                                                                   |
| ----------------------------- | ----- | --------- | -------------------------------------------------------------------------- |
| dark `text-3` on `surface-3`  | 4.23  | 4.5       | Never put `text-3` on `surface-3`; use `text-2` there (decided 2026-09-22) |
| light `text-3` on `surface-3` | 4.26  | 4.5       | same                                                                       |
| light `series-2` on `bg`      | 2.85  | 3 (marks) | Always direct-label light chart series (decided 2026-09-22)                |
| light `series-3` on `bg`      | 2.51  | 3 (marks) | same                                                                       |

Fixed: light `progress` was `#1D7F4A` on the canvas (4.47:1 on `bg`); it's now `#1C7A47` (4.77:1), decided 2026-09-22 (#18). The Tokens-board test records this as a deliberate deviation. Also fixed: light chip text on tints (was 4.08–4.39:1 over `bg`) now uses `--<c>-on-tint` (#24); the test covers every tint colour over `bg` and `surface-1`, in both themes, and checks the hue is kept.

**SafetyScreen layout (decided 2026-09-22):**

1. Eyebrow + headline: a fixed UI label per `action`, owned by the app (e.g. "See your GP"). One label per action, never per rule, and no AI input
2. Body: the matched rule's `user_message`, verbatim
3. `SourceLink`s from the rule's `sources`
4. The action buttons for that level (e.g. `tel:999`, `tel:111`)
5. `SafetyLockNote`

There's no other safety copy. The canvas's per-scenario headlines, bodies, steps and load changes ("Continue at 60 kg", "about 15%") are dropped. Load or exercise changes come only from the rule's engine action.

### 5.4 Other

- Exercise names: use `display_name ?? name`. The 111 staples have a `display_name` (e.g. "Bench press") and `aliases` since v0.1.2; other exercises fall back to `name`. Muscles: "front delts" can't be shown, the data only has `shoulders`. "Back", "Arms", "Quads" are `muscle_groups` (credit = max of members, not the sum)
- Exercise-Detail cues and steps differ from `exercises.json` `cues` / `instructions`; swaps show 3 of 6, and "Cable fly" (Swap-Sheet) isn't a bench swap. Start loads come from `tr.global.swap_starting_load`: 70 kg barbell bench → 24–25 kg dumbbells per hand, not the canvas's 26. Swap reasons come from `swap_reason`, not the canvas sentences
- Rest "2:00" is hard-coded; it's `tr.goal.*.rest_seconds`
- Loads must follow `load_convention` everywhere: "per hand" for dumbbells (Session-Detail and Lifts-Table show "22 × 10" without it), and "per side" (not "2 ×") for plate-loaded `Leverage_*` machines
- Weigh-ins: any frequency, charts show a 7-day average (decided 2026-09-22). Progress's "optional · weekly" copy goes
- e1RM: sets of ≤10 reps only (`tr.global.e1rm`); the canvas footnote says 12
- Push/pull balance (Exercise-Detail "R-02"): now `tr.global.push_pull_balance`, weak evidence, `hard_rule: false`. Show only as a gentle nudge that says no ratio is evidence-based

## 6. Design gaps and data issues

### Design gaps (canvas → design session)

- **Movement pattern icons:** `cardio`, `plyometric`, `olympic`, `mobility` have no drawing (fallbacks: bike, dumbbell)
- **Muscle map regions:** `neck`, `abductors`, `adductors` aren't drawn. The front lower leg is mapped to `calves` (the enum has no tibialis)
- **Pain-Flag sheet can't detect most red flags.** To route to the right rule it needs follow-ups for: chest-pain spread and symptoms; palpitations/dizziness and "has it settled?"; "Not sure" (`unsure_if_emergency`); crack/deformity/numbness/colour (`injury_severe`); can't bear weight, swelling, fever; calf hot/swollen (the canvas has **no Calf area**; the data has `calf` since v0.1.2); sharp vs constant, duration >7 days, swelling. Illness, urine, cycle and energy flags need a separate check-in flow (no board)
- **BodyMap** has no left/right and no joint areas (both shoulders light up for "R shoulder"). The data now has them (`enums.body_areas`, 7 sided); the drawing needs a pass in D1
- **States not drawn:** `EvidenceBadge` weak; `ReasonPicker` selected; `Switch` disabled / "coming later"; `OptionCard` disabled; `PainFlagCard` cleared; `WeekStrip` done differs between Main (check) and Today-Rest (filled)
- **Touch targets under 44px on the canvas** (D1 raises all to ≥48 via `touch.min`): Onb-Health area chips (40), docked timer Skip (36), Retry (40), Connect-AI copy (40), Progress lift chips (40), range/view toggles (36), Notif-Centre Better/Same/Worse (40) and "Open review" (32)
- **Colour misuse to fix in D1:** pain flags drawn in `swap` (use the matched safety level); "below target" in `warning`; protein `Meter` in a series colour; volume changes reuse `swap`
- **Charts:** Nutrition-Week bars start at 1,500 (must start at 0); Progress line charts have no table toggle
- **Onboarding** stops at step 3 of 5 (steps 4–5 undrawn)
- **Safety follow-ups can be switched off** in Notif-Settings; decide whether that's allowed
